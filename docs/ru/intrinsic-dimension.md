# Внутренняя размерность эмбеддингов: руководство

Как измерить **внутреннюю размерность** (intrinsic dimension, ID) наборов эмбеддингов с помощью `langembed` и как читать результаты. Код: `src/langembed/eval/intrinsic_dim.py` (оценщики) и `scripts/intrinsic_dims.py` (командная строка). Тесты: `tests/test_intrinsic_dim.py`. Английская версия: [docs/intrinsic-dimension.md](../intrinsic-dimension.md).

## 1. Что измеряется и зачем

Модель эмбеддингов переводит объекты в векторы фиксированной длины: 256 у ветки A, 768 у B и mpnet, 1024 у C, 128 у CBOW. Точки не заполняют всё это пространство, а лежат около множества гораздо меньшей размерности. Его размерность и есть **внутренняя размерность**.

ID полезна тем, что **не требует разметки**. Золотых STS-данных у большинства языков нет, а для дообучения есть лишь несколько сотен триплетов, поэтому ранжировать ветки по точности нельзя. Зато можно сравнить, сколько структуры использует каждый вариант на одних и тех же объектах, проследить ID по ходу обучения, сопоставить её с анизотропией, а там, где STS есть, — со Spearman.

Подход взят из [whiteroomlz/intrinsic-dimensions-computation](https://github.com/whiteroomlz/intrinsic-dimensions-computation): там ID наборов эмбеддингов n-грамм оценивается по минимальным остовным деревьям (MST) на Slurm-кластере. Здесь заново реализован его MST-оценщик, со следующими отличиями:

| Исходный репозиторий | Здесь |
|---|---|
| MST из C++-пакета `mst-clustering`, задачи Slurm до 720 ч | Точный алгоритм Прима на NumPy на одной машине (≈10–25 с на прогон для 10 тыс. точек) |
| Min-max-масштабирование каждого столбца, евклидово расстояние | L2-нормированные векторы (евклидово расстояние между единичными векторами = косинусная геометрия), по желанию с предварительным центрированием |
| Без фиксированного зерна | Фиксированные зёрна; каждый результат — среднее ± ст. отклонение по зёрнам |
| Оценщик BQY с эталонными таблицами только для размерностей 2–17 | Не перенесён: наши ID могут быть больше 17. Вместо него добавлены независимые проверки TwoNN и MLE |
| Результаты отправляются по почте в `.xlsx` | Файлы CSV и Markdown в папке вывода |

## 2. Оценщики

Все оценщики работают на одной и той же случайной выборке различных подготовленных векторов.

| Столбец | Оценщик | Идея | Замечания |
|---|---|---|---|
| `schweinhart_a{α}` | Длина MST (Schweinhart) | Для n точек из d-мерного множества `E_α(n) = Σ |e|^α` по рёбрам MST растёт как `n^((d-α)/d)`. Наклон `s` в лог-лог-регрессии по вложенным подвыборкам (10% → 100%) даёт `d = α / (1 - s)`. | Корректно при α < d. Сравнивайте несколько α: совпадение означает устойчивую оценку. |
| `twonn` | TwoNN (Facco и др., 2017) | Отношение `μ = r₂/r₁` расстояний до второго и первого соседа; `-log(1 - F(μ)) = d·log μ`. | Локальный и устойчивый к перепадам плотности; верхние 10% отношений отбрасываются. |
| `mle` | MLE Левины–Бикела | Максимальное правдоподобие по k ближайшим соседям, обратное усреднение (MacKay–Ghahramani), среднее по k = 10…20. | Локальный; при малом n занижает высокие ID. |
| `pca90`, `pca95` | PCA | Число компонент, объясняющих 90% / 95% дисперсии. | Линейная размерность, обычно намного больше ID искривлённого множества. Это верхний ориентир. |
| `participation_ratio` | PCA | `(Σλ)² / Σλ²` | Гладкая линейная размерность. |
| анизотропия (`meta.json`, таблица Markdown) | Средний косинус между парами исходных векторов | Около 0 — изотропно; высокое значение — все векторы смотрят в одну сторону. | При высоком значении сравнивайте `unit` и `centered`. |

Если три нелинейных оценщика (`schweinhart`, `twonn`, `mle`) совпадают в пределах нескольких единиц, ID определена хорошо. Если они сильно расходятся, множество многомасштабное (например, кластеры разной размерности): приводите разброс, а не одно число.

## 3. Входные данные

Каждый вариант — матрица, одна строка на объект:
- файл `.npy` формы `(n_объектов, размерность)`, или
- файл `.jsonl` с полем `embedding` в каждой строке, например вывод `scripts/embed_article_units_cpu.py`.

Строки должны быть **одними и теми же объектами в одном порядке** во всех вариантах. Флаг `--align` проверяет, что число строк совпадает. Используйте **различные объекты**: одинаковые строки дают одинаковые векторы и нулевые расстояния. Повторяющиеся векторы удаляются автоматически, а `n_unique_available` показывает, сколько осталось.

## 4. Запуск

На сервере, в образе `langembed-ml` (только CPU, GPU не нужен):

```bash
cd /home/s939/langembed_deploy/langembed
bash scripts/docker_run_watchdog.sh id-run 240 false scripts/intrinsic_dims.py \
    --emb A0=experiments/intrinsic_pilot/emb/A0.npy \
    --emb mpnet=experiments/intrinsic_pilot/emb/mpnet.jsonl \
    --align --out-dir experiments/intrinsic_pilot/results
```

Параметры:

| Параметр | По умолчанию | Значение |
|---|---|---|
| `--emb ИМЯ=ПУТЬ` | (обязателен, можно повторять) | Вариант эмбеддингов. |
| `--preps` | `unit centered` | `unit`: L2-нормирование. `centered`: вычесть средний вектор, затем L2-нормировать. |
| `--seeds` | `0 1 2 3 4` | Своя случайная выборка и порядок подвыборок на каждое зерно. |
| `--sample-size` | `10000` | Точек на зерно. Память ≈ 3 × 8 × n² байт (около 2,4 ГБ при 10 тыс., 9,6 ГБ при 20 тыс.). |
| `--n-sizes` | `10` | Число вложенных размеров подвыборок для MST-оценщика. |
| `--alphas` | `0.5 1 2` | Показатели степени MST-оценщика. |
| `--align` | выкл. | Ошибка, если у вариантов разное число строк. |

Локально, без Docker: `PYTHONPATH=src python scripts/intrinsic_dims.py ...` (нужен numpy).

Время работы на corpus-host — около 15–30 с на вариант × подготовку × зерно при 10 тыс. точек. Оценщики написаны на чистом NumPy и работают в одном процессе.

## 5. Результаты

В `--out-dir`:
- `results.csv`: одна строка на вариант × подготовку × зерно со всеми оценщиками.
- `summary.csv`: среднее и стандартное отклонение по зёрнам.
- `summary.md`: та же сводка таблицей Markdown.
- `meta.json`: аргументы, анизотропия, формы матриц и время работы.

Стандартное отклонение по зёрнам — это уровень шума. Различия между вариантами меньше примерно двух стандартных отклонений незначимы.

## 6. Оговорки

- **Нормирование:** проекция на единичную сферу может уменьшить ID не более чем на 1. Это правильная геометрия для моделей, обученных на косинусе.
- **Анизотропия:** при высоком среднем косинусе (у SimCSE `A0` ≈ 0,5–0,7) расстояния после нормирования определяются общим направлением. Сравнивайте с `centered`.
- **Конечные выборки:** все оценщики занижают ID, когда истинная ID велика, а n мало. Сравнивайте варианты при **одинаковом** n; абсолютные числа при разных n не сравнивайте.
- **Выбор α для MST-оценщика:** результат намного больше α — это нормально. Если `schweinhart_a2` ≫ `schweinhart_a0.5`, режим масштабирования не достигнут; увеличьте n.
- **Набор объектов:** ID описывает набор объектов не меньше, чем модель. Фразы, предложения и словарь дают разные числа, поэтому модели сравнивают на одинаковых объектах.

## 7. Какие эксперименты это позволяет

1. **Сравнение веток без разметки:** A0/A/B/C/CBOW и внешние модели на одних и тех же объектах (пилот ниже).
2. **ID и STS по языкам:** для языков с `eval.json` (hi, ta, gu, kn, mr, or, pa, ur) проверить, связана ли ID со Spearman.
3. **Повторение исходного репозитория на n-граммах:** матрицы n-грамм из векторов CBOW или словаря (n = 1–3) по каждому языку.
4. **Динамика обучения:** ID на каждом этапе (MLM-предобучение → SimCSE → обучение с учителем).
5. **Анизотропия:** `unit` против `centered` и отбеливания, в связи с качеством кластеров семантического графа.
6. **Выбор длины вектора:** обрезка PCA примерно до ID с измерением падения STS.
7. **Кластеризация по MST:** разрезание самых длинных рёбер MST (Zahn) как альтернатива построителю семантического графа на k-NN + Louvain.

## 8. Пилот (11.10.2026)

10 243 различные английские фразовые единицы из сравнения веток на 10 статьях (`experiments/branches10`): A0 (`simcse_en`), A (`embed_en_svd`), B, C, CBOW и `sentence-transformers/all-mpnet-base-v2`. 5 зёрен, подготовки `unit` и `centered`. Входные данные лежат в `experiments/intrinsic_pilot/` на corpus-host (`pilot_prepare.py` строит выровненные матрицы).

Результаты (среднее ± ст. отклонение по 5 зёрнам, подготовка `unit`; у `centered` нелинейные оценки отличаются меньше чем на 1; полная таблица — `experiments/intrinsic_pilot/results/summary.md`):

| Вариант | Размерность | Анизотропия | TwoNN | MLE | MST α=0.5 | MST α=1 | MST α=2 | PCA 90% | Participation ratio |
|---|---|---|---|---|---|---|---|---|---|
| A0 (`simcse_en`) | 256 | 0,52 | 13,0 | 14,1 | 13,5 ± 0,9 | 13,5 ± 0,8 | 13,6 ± 0,7 | 66 | 25,2 (centered 13,6) |
| A (`embed_en_svd`) | 256 | 0,65 | 13,4 | 14,3 | 13,9 ± 0,8 | 13,9 ± 0,8 | 13,9 ± 0,7 | 65 | 15,9 |
| B (многоязычная база) | 768 | 0,25 | 6,4 | 8,7 | 8,2 ± 0,1 | 8,6 ± 0,1 | 9,1 ± 0,1 | 128 | 64,7 |
| C (LLM-эмбеддер) | 1024 | 0,83 | 7,2 | 11,3 | 10,2 ± 0,4 | 10,6 ± 0,4 | 11,3 ± 0,4 | 312 | 51,4 |
| CBOW (средние векторы слов) | 128 | 0,03 | 6,9 | 10,3 | 9,6 ± 1,5 | 9,9 ± 1,6 | 10,5 ± 2,0 | 106 | 98,7 |
| mpnet (`all-mpnet-base-v2`) | 768 | 0,13 | 6,1 | 7,6 | 7,9 ± 0,1 | 8,3 ± 0,2 | 9,0 ± 0,2 | 258 | 123,5 |

Что показал пилот:

- **Оценщики согласованы.** У каждого варианта TwoNN, MLE и MST-оценщик расходятся не более чем примерно на 3, а MST-оценка почти не зависит от α. Наборы фраз имеют чётко определённую ID ≈ 6–14 — намного меньше длины векторов 128–1024.
- **A0 и A образуют отдельную группу, около 13–14.** Все остальные варианты, включая внешнюю модель mpnet, лежат около 6–11. Дообучение ветки A по SVD-разметке не изменило ID основы SimCSE (13,5 → 13,9).
- **Линейная и нелинейная структуры совершенно разные.** A0 и A почти плоские (participation ratio 16–25, близко к ID). mpnet занимает около 258 линейных направлений (90% дисперсии), но её ID лишь ≈ 7–8, т.е. это сильно искривлённая структура малой размерности. CBOW почти изотропна (анизотропия 0,03, participation ratio 99) при ID ≈ 10.
- **Центрирование** важно для линейных характеристик анизотропных вариантов (participation ratio A0 25,2 → 13,6), но не для нелинейной ID, которая использует только локальные расстояния.
- **Это не рейтинг качества.** Связана ли меньшая или большая ID с лучшим STS, должен показать эксперимент 2 (ID и STS по языкам). То, что у mpnet, сильной общей модели, самая низкая ID, — гипотеза для проверки, а не вывод.

Ограничения пилота:

- Различных фраз всего 10 243, поэтому каждое зерно берёт 10 000 почти одних и тех же точек. Разброс по зёрнам отражает в основном порядок подвыборок MST, а у TwoNN/MLE он ±0,0. Чтобы получить настоящий уровень шума, берите `--sample-size` заметно меньше числа объектов или больше объектов.
- Только английские фразовые единицы, одна предметная область (10 научных статей) и один тип объектов.
